IchiPing UNO Q 移植方針・センサ接続・GPIO

対象: Arduino UNO Q（QRB2210 Linux + STM32U585 / Zephyr）

1. 開発方針

IchiPingの信号処理・32状態ラベル・学習資産を引き継ぎ、ボード依存層だけをUNO Qへ置き換える。リアルタイムI/OはSTM32U585、モデル推論・ログ・将来のネットワーク機能はDebian Linux側に置き、Arduino Router Bridgeで接続する。

  1. Phase 0 — bring-up: Matrix、Bridge、GPIO、PCA9685検出を実機確認する。
  2. Phase 1 — actuator: PCA9685の校正値と5台のSG90制御を移植する。
  3. Phase 2 — acoustic: USB Audioを第一候補として16 kHzモノラル録音・ping再生を確立する。
  4. Phase 3 — inference:既存モデルと特徴量処理をLinux側へ移し、実測データで同値性を検証する。
  5. Phase 4 — standalone:起動時実行、ログ、ネットワーク通知を統合する。

内蔵STM32管理8×13 LED MatrixArduino_LED_Matrix、外部GPIO消費なし

電圧: MCU GPIOは3.3 Vロジック。公式資料ではA0/A1以外は5 V tolerantだが、周辺機器は原則3.3 Vで統一する。PCA9685はVCC=3.3 V、サーボ電源V+=外部5 Vとし、UNO Q・PCA9685・サーボ電源のGNDを共通化する。サーボをUNO Qの3.3 V端子から給電しない。

3. センサ・アクチュエータ接続

機器UNO Q接続移植判断
PCA9685VCC→3V3、GND→GND、SDA→D20、SCL→D21、V+→外部5 VPhase 0で0x40 ACKを検査。Phase 1で既存の5ch座標・校正を移植。
SG90 ×5PCA9685 ch 0–4既存のa/b/c/AB/BC順を維持。外部5 V電源を使用。

MAX98357A未割り当て同上。未検証の下部コネクタ配線は採用しない。
音響の第一候補: 給電対応USB-Cハブ + Linux互換USB Audioデバイスを使い、Debian側で16 kHz / mono / PCMの同時再生・録音を行う。IchiPingの既存INMP441/MAX98357Aを必ず継続する場合は、JMISC/高速コネクタのSAI信号とZephyrドライバ対応を別途検証してから配線を確定する。

4. LED Matrixの表示規約

左から5個のセルが窓a、窓b、窓c、扉AB、扉BC。明るいセルは開、暗いセルは閉。右端は下から伸びる信頼度バー。ping／推論中は中央から広がる菱形アニメーションを表示する。

5. Phase 0 合格条件

  • UNO QがUSBでCOM/ADBの両方として認識される。
  • App Labアプリがビルドされ、STM32スケッチとLinux Pythonが起動する。
  • Router Bridge経由で状態値と信頼度をMatrixに表示できる。
  • D3–D7、D8、D9を安全に読み取れる。
  • PCA9685接続時は0x40を検出し、未接続時もアプリが継続する。
